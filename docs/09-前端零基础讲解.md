# 09 前端零基础讲解：把 web/ 这个工程一句句讲明白

这份文档假设你没写过前端，不知道 Vue、不知道什么是组件、没听过"双向绑定"。
目标只有一条：让你看着 `web/` 里的真实文件，能读懂每一行在干什么，以及登录这件事是怎么从"你打字"到"页面跳走"的。

## 第 1 节 先建立一张全局地图

### 1.1 前端到底是个啥

后端（`cmd/`、`internal/`）是一个 Go 程序，它躲在你的电脑里，对外提供"接口"。
比如你说"我要登录，用户名 hunter，密码 12345678"，后端算一算，回你一个"登录成功 + 一个 token 令牌"。

前端是跑在浏览器里的页面。它干两件事：
- 把你输入的账号密码，打包发给后端接口。
- 把后端回的数据，画成你能看见、能点的界面。

`web/` 这个文件夹就是一个前端工程。它自己不能存数据，所有数据都来自那个 Go 后端。

### 1.2 工程目录长啥样（先有个印象，不用背）

```
web/
  package.json        # 工程的"购物清单"：需要哪些外部库
  vite.config.ts      # 开发服务器配置，含 /api 代理
  index.html          # 浏览器打开的第一个空壳页面
  src/
    main.ts           # 整个应用从这里启动
    App.vue           # 最外层的根组件
    styles/index.css  # 全局样式
    utils/
      auth.ts         # token 的存取（localStorage）
      request.ts      # 真正发 HTTP 请求的地方（仿 vue3-element-admin）
    api/
      user.ts         # 声明"有哪些用户相关接口"
    store/modules/
      user.ts         # 登录状态仓库（Pinia）
    router/index.ts   # 网址 和 页面 的对应关系
    layout/           # 登录后看到的框架（左边菜单 + 顶栏 + 中间内容）
    views/            # 各个具体页面（登录、注册、文章…）
```

### 1.3 怎么把它跑起来

打开终端，进入 `web/` 目录，依次执行：

```
cd web
npm install
npm run dev
```

`npm install` 是按 `package.json` 的清单，把需要的库下载到本地。
`npm run dev` 启动开发服务器，终端会打印一个网址，通常是 `http://localhost:5173`，浏览器打开它就能看到页面。

> 开发时前端跑在 5173 端口，后端跑在 8080 端口。两个端口不一样，浏览器不允许前端直接敲后端地址（这叫跨域）。解决办法在 `vite.config.ts`：凡是前端请求 `/api` 开头的地址，Vite 自动转发到 `127.0.0.1:8080` 的后端。所以前端代码里写 `/api/login`，实际命中的是后端。

## 第 2 节 必须先懂的四个词

### 2.1 组件（Component）

组件是界面上一块"独立、可复用"的部分。一个按钮可以是一个组件，一整个登录表单也可以是一个组件。

在 Vue 里，**一个组件就是一个 `.vue` 文件**。它分成三块，写在一个文件里：

```vue
<template>
  <!-- 这里写"长什么样"：用类似 HTML 的标签描述结构 -->
</template>

<script setup lang="ts">
  // 这里写"怎么动"：变量、函数、逻辑，用 JavaScript/TypeScript
</script>

<style scoped>
  /* 这里写"好不好看"：CSS 样式。scoped 表示只作用在当前组件 */
</style>
```

你看到的每个页面文件（`views/login/index.vue`、`layout/index.vue` 等）都是一个组件。

### 2.2 表单组件从哪来（这是你问的重点）

`el-form`、`el-input`、`el-button` 这些带 `el-` 前缀的标签，**不是我们自己写的，也不是 Vue 自带的**。它们来自一个别人做好的组件库，叫 **Element Plus**。

它从哪来，分三步理解：

第一步，它是一个外部库，写在 `package.json` 的"依赖"清单里：

```json
"dependencies": {
  "element-plus": "^2.8.4",
  "@element-plus/icons-vue": "^2.3.1"
}
```

`npm install` 时，npm 就是按这个清单把 Element Plus 下载进来的。

第二步，工程启动时，在 `src/main.ts` 里把整个库"安装"到应用上：

```ts
import ElementPlus from 'element-plus'
app.use(ElementPlus)
```

`app.use(ElementPlus)` 这句话的意思是：把 Element Plus 提供的所有组件（按钮、表单、卡片、菜单…）一次性注册到全局。

第三步，注册之后，**任何 `.vue` 文件里都能直接写 `<el-button>`、`<el-input>`，不用再单独 import**。这就是"来源"：库（package.json）→ 全局安装（main.ts）→ 页面直接使用。

图标也一样。`main.ts` 里这段：

```ts
import * as ElementPlusIconsVue from '@element-plus/icons-vue'
for (const [key, component] of Object.entries(ElementPlusIconsVue)) {
  app.component(key, component)
}
```

它把 Element Plus 的所有图标组件也注册成全局组件。所以侧边栏里你能直接写 `<Document />`、`<Bell />` 这样的图标，不用 import。

> 辩证地看：用现成组件库省了我们手画按钮、手写样式的大量功夫，代价是打包体积变大（你之前看到的那个 1.2MB 的警告就来自这里）。对学习和后台项目，这个取舍是划算的；对极致性能要求的场景才需要按需引入。

### 2.3 双向绑定 v-model（你问的另一个重点）

先给一句话定义：**v-model 把一个"输入框"和一个"变量"绑在一起。你往框里打字，变量跟着变；你改了变量，框里显示也跟着变。** 两个方向都同步，所以叫"双向"。

看一个最小例子：

```vue
<template>
  <el-input v-model="name" />
  <p>你刚才输入的是：{{ name }}</p>
</template>

<script setup lang="ts">
import { ref } from 'vue'
const name = ref('')
</script>
```

解释：
- `ref('')` 创建一个响应式变量 `name`，初始是空字符串。响应式意思是：它的值一变，界面会自动重画。
- `v-model="name"` 贴在输入框上，意思是"这个框的内容，绑定到 `name` 变量"。
- 你在框里打字，`name` 立刻变成你打的字。
- `{{ name }}` 是 Vue 的"插值"语法，把变量的值显示到页面上。所以你一边打，下面那行字一边跟着变。

这就是双向绑定。它替你省掉了"监听输入事件 → 手动读输入框的值 → 手动赋值给变量"这一串样板代码。代价是初学者容易忽略"背后其实发生了同步"，所以这里特意点明。

### 2.4 响应式变量 ref 和 reactive

Vue 里普通变量改了，界面不会自动更新。必须用 Vue 提供的 `ref` 或 `reactive` 包一下，它才"响应式"。

- `ref(值)`：包一个单一的值。读它要写 `xxx.value`。比如 `const loading = ref(false)`，用的时候是 `loading.value`。
- `reactive({...})`：包一个对象。对象里的属性直接读，不用 `.value`。比如 `const form = reactive({ username: '', password: '' })`，用 `form.username` 即可。

登录页同时用到了两者，下面会看到。

## 第 3 节 拆解登录页：每个标签是啥，逻辑怎么走

文件：`src/views/login/index.vue`。我们一段段看。

### 3.1 模板部分（页面长什么样）

```vue
<el-card class="auth-card">
  <h2>登录</h2>
  <el-form
    ref="formRef"
    :model="form"
    :rules="rules"
    label-width="80px"
    @keyup.enter="onSubmit"
  >
    <el-form-item label="用户名" prop="username">
      <el-input v-model="form.username" placeholder="3-32 位字母数字下划线" />
    </el-form-item>
    <el-form-item label="密码" prop="password">
      <el-input v-model="form.password" type="password" show-password />
    </el-form-item>
    <el-form-item>
      <el-button type="primary" :loading="loading" @click="onSubmit">登录</el-button>
      <el-button @click="goRegister">去注册</el-button>
    </el-form-item>
  </el-form>
</el-card>
```

逐个标签解释：

- `<el-card>`：Element Plus 的卡片容器，就是带圆角和阴影的白底方块，用来装表单。
- `<el-form>`：表单容器。它身上有几个关键属性：
  - `:model="form"` 冒号表示"绑定一个变量"，这里把表单绑到脚本里的 `form` 对象。表单校验、取值都基于这个对象。
  - `:rules="rules"` 绑定校验规则（哪些字段必填、错了提示啥）。
  - `ref="formRef"` 给这个表单起个内部名字 `formRef`，脚本里靠它来触发"校验"。
  - `@keyup.enter="onSubmit"` `@` 是"监听事件"，`keyup.enter` 是"在输入框按回车键"。意思是按回车就执行 `onSubmit` 函数。
- `<el-form-item>`：表单项，负责排版（左边的文字标签 + 右边的控件）。`label="用户名"` 是左边显示的字，`prop="username"` 告诉表单"这一项对应 `form.username`"，校验规则靠它对应。
- `<el-input v-model="form.username" />`：输入框，用 v-model 双向绑定到 `form.username`。你打字，账号就进 `form.username`；密码框同理绑到 `form.password`。`type="password"` 让输入变成小圆点，`show-password` 给一个眼睛图标切换显示。
- `<el-button>`：按钮。`type="primary"` 是蓝色主按钮；`:loading="loading"` 绑定 `loading` 变量，为真时按钮转圈禁用，防止重复点击；`@click="onSubmit"` 点击触发登录函数。`@click="goRegister"` 点"去注册"跳到注册页。

### 3.2 脚本部分（页面怎么动）

```ts
import { reactive, ref } from 'vue'
import { useRouter } from 'vue-router'
import { ElMessage, type FormInstance, type FormRules } from 'element-plus'
import { useUserStore } from '@/store/modules/user'

const router = useRouter()
const userStore = useUserStore()
const formRef = ref<FormInstance>()
const loading = ref(false)

const form = reactive({ username: '', password: '' })
const rules: FormRules = {
  username: [{ required: true, message: '请输入用户名', trigger: 'blur' }],
  password: [{ required: true, message: '请输入密码', trigger: 'blur' }],
}
```

逐行解释：

- `import ... from 'vue'` 引入 Vue 的能力。`reactive`、`ref` 是上面讲过的响应式工具。
- `useRouter()` 拿到"路由控制对象"，脚本里用它来跳页面（比如 `router.replace('/articles')`）。
- `ElMessage` 是 Element Plus 的"轻提示"，一行小字弹在右上角。`FormInstance`、`FormRules` 是 TypeScript 的类型，帮编辑器检查你写的表单和规则对不对。
- `useUserStore()` 拿到"用户仓库"，后面调 `userStore.login(...)` 发登录请求。这个仓库在第 5 节讲。
- `formRef = ref()` 对应模板里 `ref="formRef"`，用来在脚本里调用表单的校验方法。
- `loading = ref(false)` 一开始不转圈；点登录后设成 true，结束设回 false。
- `form = reactive({ username: '', password: '' })` 这就是表单绑定的数据对象，初始都是空字符串。用户在输入框打字，这里的值就实时更新。
- `rules` 是校验规则：用户名和密码都 `required: true`（必填），没填就提示对应文字。`trigger: 'blur'` 表示"失去焦点时校验"。

核心函数 `onSubmit`：

```ts
async function onSubmit() {
  if (!formRef.value) return
  const valid = await formRef.value.validate().catch(() => false)
  if (!valid) return
  loading.value = true
  try {
    await userStore.login({ ...form })
    ElMessage.success('登录成功')
    router.replace('/articles')
  } finally {
    loading.value = false
  }
}
```

把它读成一句句人话：

1. 如果表单引用不存在，直接退出。
2. `formRef.value.validate()` 触发校验，返回"通过 / 不通过"。`await` 表示等它算完。`catch(() => false)` 是兜底：万一报错就当不通过。
3. 校验没过，直接退出，不往下走。
4. 把 `loading` 设成 true，按钮转圈。
5. `await userStore.login({ ...form })` 调用用户仓库的登录方法，把 `{用户名, 密码}` 传进去。`await` 等后端回结果。这一步内部怎么发请求，第 4、5 节展开。
6. 成功就弹"登录成功"，并 `router.replace('/articles')` 跳到文章列表页。
7. `finally` 里无论成功失败，都把 `loading` 设回 false，按钮恢复可点。

`{ ...form }` 是"把 form 对象里的字段摊开"成一个新对象传给函数，等价于 `{ username: form.username, password: form.password }`。

### 3.3 把双向绑定串起来看（重点回顾）

你打账号 → `v-model="form.username"` 把字写进 `form.username` → 点登录 → `onSubmit` 读 `form.username` 和 `form.password` 发给后端。

反过来，如果某处代码写了 `form.username = 'hunter'`，页面输入框里也会立刻显示 hunter。这就是"双向"。

## 第 4 节 请求从哪发出去：api/user.ts 和 utils/request.ts

登录函数里那句 `userStore.login(...)` 最终会发一个 HTTP 请求。请求分两层。

### 4.1 接口声明层 api/user.ts

这一层只"列清单"，不真正发请求：

```ts
import request from '@/utils/request'

export function login(data: { username: string; password: string }) {
  return request<LoginResp>({ url: '/login', method: 'post', data })
}
```

意思是：登录这个动作，请求地址是 `/login`，方法是 POST，带上 `data`（账号密码），并且约定返回的数据形状是 `LoginResp`。
`@/utils/request` 里的 `@` 是别名，等于 `src/` 目录，所以 `@/utils/request` 就是 `src/utils/request.ts`。

### 4.2 真正发请求层 utils/request.ts

这是仿照 `vue3-element-admin` 写的 axios 封装。核心思路是"拦截器"：请求真正飞出去之前、响应飞回来之后，都先经过我们写的一段统一处理。

请求拦截器（发送前自动加 token）：

```ts
service.interceptors.request.use((config) => {
  const token = getToken()
  if (token) {
    config.headers.set('Authorization', `Bearer ${token}`)
  }
  return config
})
```

解释：每次发请求，先看本地有没有 token（登录后才有）。有就自动在请求头加上 `Authorization: Bearer xxx`。这样每个需要登录的接口都不用自己手写加 token。

响应拦截器（回来后自动拆包）：

后端返回的格式固定是 `{ code, message, data }`（见后端 `pkg/response`）。成功时 `code` 是 0，业务数据在 `data` 里。拦截器把 `data` 直接掏出来：

```ts
service.interceptors.response.use(
  (response) => {
    const res = response.data
    if (res && res.code === 0) {
      return res.data          // 页面拿到的是 data 本身，不用再 .data.data
    }
    ElMessage.error(res?.message || '请求失败')
    return Promise.reject(new Error(res?.message || 'Error'))
  },
  (error) => {
    // 失败分支：401 清登录态跳登录页；429 提示"请求过于频繁"
  }
)
```

所以页面里写 `const resp = await login(...)`，拿到的 `resp` 已经是后端 `data` 里的 `{ token, user }`，不用再剥一层。

> 辩证地看：拦截器把"加 token、拆包、统一报错"集中在一处，页面代码变干净。但代价是新人看页面时看不见这些动作，容易以为"发请求就一行"。这里把它摊开讲，是为了让你知道底下还有一层。

## 第 5 节 登录状态存哪：store/modules/user.ts（Pinia）

`useUserStore` 来自这里。Pinia 是"全局状态仓库"，可以理解成一个全应用共享的盒子，任何页面都能往里读、往里写。

```ts
export const useUserStore = defineStore('user', () => {
  const token = ref(getToken())
  const username = ref('')

  async function login(data) {
    const resp = await loginApi(data)   // 调第 4 节的 api
    token.value = resp.token
    username.value = resp.user.username
    setToken(resp.token)                // 存进 localStorage
    return resp
  }

  function resetToken() {
    removeToken()
    token.value = ''
    username.value = ''
  }

  return { token, username, login, resetToken }
})
```

要点：
- `login` 内部调用 `api/user.ts` 的 `loginApi`，拿到 `{ token, user }`，把 token 和用户名存进仓库，同时 `setToken` 写进浏览器的 `localStorage`（见 `utils/auth.ts`）。
- 写进 `localStorage` 的好处：刷新页面 token 不丢，不用重新登录。
- `resetToken` 用于退出登录或登录过期时清空状态。

## 第 6 节 页面怎么跳：router/index.ts

路由 = "网址" 和 "页面组件" 的对应表。

```ts
const routes = [
  { path: '/login', component: () => import('@/views/login/index.vue') },
  { path: '/register', component: () => import('@/views/register/index.vue') },
  {
    path: '/',
    component: Layout,
    redirect: '/articles',
    children: [
      { path: 'articles', component: () => import('@/views/article/index.vue') },
      { path: 'hot', component: () => import('@/views/hot/index.vue') },
      { path: 'notifications', component: () => import('@/views/notification/index.vue') },
    ],
  },
]
```

- 访问 `/login` 就显示登录页组件；访问 `/register` 显示注册页。
- `/` 是登录后的整体框架 `Layout`，它内部有个 `<router-view />`，会被替换成子路由对应的页面。`redirect: '/articles'` 表示进 `/` 自动转到 `/articles`。
- `import(...)` 这种写法叫"懒加载"，用到哪个页面才加载哪个文件，首屏更快。

路由守卫（没登录就拦）：

```ts
router.beforeEach((to) => {
  const token = getToken()
  const isPublic = to.meta.public === true
  if (token) {
    return isPublic ? '/articles' : true
  }
  return isPublic ? true : '/login'
})
```

读成人话：每次准备跳转前，看本地有没有 token。
- 有 token：如果还想去登录/注册页，直接送回文章页；否则放行。
- 没 token：只有"公开页"（登录、注册）能进，其它一律踢到 `/login`。

## 第 7 节 登录后的框架：layout + 侧边栏 + 顶栏

登录成功后看到的界面，是 `src/layout/index.vue` 搭的：

```vue
<el-container>
  <el-aside width="200px" class="sidebar-container">
    <div class="logo">论坛</div>
    <Sidebar />
  </el-aside>
  <el-container>
    <el-header class="navbar"><Navbar /></el-header>
    <el-main><router-view /></el-main>
  </el-container>
</el-container>
```

- `el-container` / `el-aside` / `el-header` / `el-main` 都是 Element Plus 的布局组件，负责把页面切成"左窄栏 + 右上顶栏 + 右中内容区"。
- `<Sidebar />` 和 `<Navbar />` 是我们自己写的子组件（在 `layout/components/` 下）。一个组件里可以放另一个组件，像搭积木。
- `<router-view />` 是占位符：当前网址对应的子页面（文章、热榜、通知）会渲染到这里。所以你点左侧菜单切换，中间内容变，框架不变。

侧边栏 `Sidebar.vue` 用 `el-menu` 画菜单，菜单项 `index="/articles"` 这种写法配合 `router` 属性，点一下就跳到对应网址。当前网址匹配的菜单项会自动高亮。

## 第 8 节 一次完整登录，从头到尾走一遍

把上面几节串成一条时间线：

1. 浏览器打开 `localhost:5173`，路由守卫发现没 token，把你送到 `/login`。
2. 登录页渲染出来：`el-form` 里两个 `el-input` 通过 `v-model` 分别绑到 `form.username`、`form.password`。
3. 你输入账号密码。每敲一个字，`form` 对象里对应字段实时更新（双向绑定）。
4. 你点"登录"按钮，`@click="onSubmit"` 触发 `onSubmit`。
5. 表单先校验（用户名密码非空），不过就弹错退出。
6. 通过则 `loading` 转圈，调用 `userStore.login(form)`。
7. 仓库调 `api/user.ts` 的 `login`，它委托 `request.ts` 发 `POST /api/login`。请求拦截器自动在头上加（此时还没有 token，所以不加）。
8. Vite 把 `/api/login` 代理到后端 `127.0.0.1:8080`。
9. 后端校验账号密码，成功返回 `{ code:0, data:{ token, user } }`。
10. 响应拦截器看到 `code:0`，把 `data` 掏出来交还给 `login`。
11. 仓库把 `token` 存进 `localStorage`，并把用户名记进仓库。
12. `onSubmit` 收到结果，弹"登录成功"，`router.replace('/articles')` 跳走。
13. 路由守卫这次看到有 token，放行，文章列表页（目前是占位页）在 `layout` 的 `router-view` 里渲染出来。
