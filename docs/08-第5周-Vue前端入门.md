## 1. 起步前：认清哪些已经替你写好了

### 1.1 地基文件（只读，这一阶段不用改）

| 文件 | 已经替你做了什么 | 你为什么先别碰 |
| --- | --- | --- |
| `src/main.ts` | `app.use(ElementPlus)` 全局注册了组件库，还把图标全部注册成全局组件 | 所以页面里可以直接写 `<el-button>`，不用每个文件 import |
| `vite.config.ts` | `/api` 代理到 8080，`ws: true` | 浏览器访问 `/api/login` 会转到 Go 后端，不用后端开 CORS |
| `src/utils/request.ts` | axios 实例；请求拦截器自动加 `Authorization: Bearer`；响应拦截器把 `{code,message,data}` 拆包，并统一弹错误提示 | 页面里拿到的就是 `data` 本身，别再写 `res.data.data` |
| `src/utils/auth.ts` | token 存 `localStorage` 的 `forum_token` | 刷新页面登录态还在 |
| `src/api/user.ts` | `login()` 和 `register()` 已经写好，带 TypeScript 类型 | 你只要调函数，不用自己拼 URL |
| `src/store/modules/user.ts` | Pinia store，登录成功时调 `setToken` 并记住用户名 | 步骤 7 用一次就够 |
| `src/router/index.ts` | 路由表已指向 `@/views/login/index.vue`，并有登录守卫 | 文件名和路径要对上，否则路由找不到组件 |
| `src/styles/index.css` | `.auth-container`、`.auth-card` 等居中样式已写好 | 直接套 class，不用自己写 flex |

**结论**：这一阶段你只写页面文件。地基读一遍知道它干了什么就行，不用改，也不用先学 Pinia 和拦截器内部实现。

### 1.3 先把工程跑起来

在 `web/` 目录下执行：

```
npm install
npm run dev
```

浏览器打开 `http://localhost:5173/login`。终端出现 `Local: http://localhost:5173/` 就说明开发服务器起来了。后端没起的话页面能显示，但发请求会失败，这一步只验证页面能打开。

### 1.4 第一个接口页面的契约

来自 `internal/router/router.go`、`internal/user/handler.go`、`internal/user/service.go`、`pkg/response/response.go`。

| 项 | 值 |
| --- | --- |
| 方法路径 | `POST /api/login` |
| 请求体 | `{"username":"...","password":"..."}` |
| 需要 token | 不需要 |
| 成功 | HTTP 200，`{"code":0,"message":"ok","data":{"token":"...","user":{"id":1,"username":"...","created_at":"...","updated_at":"..."}}}` |
| 失败 | HTTP 400 或 401，`{"code":1,"message":"...","data":null,"error_code":"...","request_id":"..."}` |
| 用户名规则 | 长度 3 到 32 |
| 密码规则 | 长度 8 到 72 字节 |
| 限流 | 按客户端 IP 分桶，容量 10，每秒补 2 个。连点会 429 |

`login()` 返回的是拆包后的 `data`，所以 `await login(...)` 直接得到 `{token, user}`。

## 2. 怎么自己在 Element Plus 里找组件

### 2.1 先判断这块属于哪一类

官网总览页按用途分组，当前分组和数量如下：

| 分组 | 个数 | 什么时候来这找 |
| --- | --- | --- |
| Basic | 12 | 按钮、图标、布局容器 |
| Form | 25 | 要让用户输入东西 |
| Data | 23 | 要把数据显示出来 |
| Navigation | 9 | 菜单、标签页、面包屑 |
| Feedback | 10 | 提示、弹窗、加载态 |
| Others / Configuration | 3 | 分割线、全局配置 |

登录页主要用 Basic（Button）、Form（Input、Form）、Feedback（Message）三类，想要白底容器时再去 Data 里找 Card。

### 2.2 三条找法

1. 打开总览页，按上表点进组件名，组件文档页上有多个示例和一张 API 属性表。
2. 示例区域一般有展开源码的开关，点开能看 `.vue` 全文。官网改版后开关位置可能变，找不到就走第 3 条。
3. 直接翻官方仓库 `docs/examples/<组件名>/` 目录，一个示例一个 `.vue` 文件。本文贴的源码都来自这里，路径会逐步标出来。

本文会用到的组件文档直链：

| 组件 | 文档页 | 官方示例目录 |
| --- | --- | --- |
| Button | https://element-plus.org/en-US/component/button | `docs/examples/button/` |
| Input | https://element-plus.org/en-US/component/input | `docs/examples/input/` |
| Form | https://element-plus.org/en-US/component/form | `docs/examples/form/` |
| Card | https://element-plus.org/en-US/component/card | `docs/examples/card/` |
| Message | https://element-plus.org/en-US/component/message | `docs/examples/message/` |

**看文档时的顺序**：先看示例知道长什么样，再看 API 表确认属性名和取值，最后才动手写。属性名写错，Vue 通常不报错，只是没效果，最难查。

### 2.3 版本提醒（重要）

`package.json` 装的是 `element-plus: ^2.8.4`，官网文档当前已经带 2.9 到 2.14 新增的组件和属性，例如 Button 的 `dashed`、Input OTP。照抄最新示例，可能报属性不认识或者干脆没效果。

本文只使用 2.8.4 已有的能力：`el-button`、`el-input`（含 `show-password`）、`el-form` / `el-form-item`、`el-card`、`ElMessage`。下面贴官方源码时，遇到新版属性会明确标注删减。

## 3. 第一个接口页面：登录页（`POST /api/login`）

### 3.0 为什么先做这一页

| 理由 | 说明 |
| --- | --- |
| 它不需要前置登录态 | `router/index.ts` 的守卫会把没 token 的人挡回 `/login`，其他页面得先有 token 才能进 |
| 请求函数已写好 | `api/user.ts` 的 `login()` 现成，你只用管页面怎么收集输入、怎么调、怎么显示结果 |
| 组件覆盖面刚好 | 一页就能练到按钮、输入框、表单校验、消息提示，Element Plus 最典型的四类 |

### 3.1 步骤总览

| 步骤 | 这一步加什么 | 跑通的判据 |
| --- | --- | --- |
| 1 | 一个只有标题的空页面 | `/login` 能看到字 |
| 2 | 一个 el-button | 页面出现蓝色按钮 |
| 3 | 按钮点击后发一次登录请求 | Network 里出现 200 的 `POST /api/login` |
| 4 | 两个 el-input 接住用户输入 | 请求体变成你打的字 |
| 5 | el-form 包起来并加校验 | 空输入被拦下，不发请求 |
| 6 | loading 与消息提示 | 请求中按钮转圈，成功与失败都有反馈 |
| 7 | 存 token 并跳转 | 登录后停在文章列表，刷新不掉 |

步骤 2 和步骤 3 之间插了一个「可选一步」，只练怎么找展示型 UI 组件，跳过它也能做完全部 7 步。

### 步骤 1：先让一个空页面能被访问

**这一步干什么**

在 `src/views/login/` 下建 `index.vue`，模板里只放一行标题，脚本先留空。

**为什么这么干**

先确认「路由配置 → 文件位置 → 浏览器渲染」这条线是通的。一上来就写 80 行表单，一旦白屏，分不清是路由没对上、组件名写错，还是请求报错。空页面把变量压到最少。

**去哪找组件**

这一步不需要组件。

**你动手**

新建 `src/views/login/index.vue`。`<template>` 里放一个 `<h2>` 写「登录」，`<script setup lang="ts">` 先空着。注意 router 里写的是 `component: () => import('@/views/login/index.vue')`，路径和文件名必须和它一致。想练从零写，先把现有成品改名备份。

**验收**

`npm run dev` 后打开 `http://localhost:5173/login`，看到「登录」两个字，控制台没有红色报错。

### 步骤 2：放一个按钮，确认组件库能用

**这一步干什么**

往页面里加一个 Element Plus 按钮。

**为什么这么干**

验证 `main.ts` 里的 `app.use(ElementPlus)` 真的生效了。这是整个组件库能不能用的最小测试，比写完整个表单再发现标签没注册要省事。

**去哪找**

Overview → Basic → Button。官方示例 `docs/examples/button/basic.vue`。

**官方源码**

下面是官方文件的节选，只留最基础的两行：

```vue
<template>
  <div class="button-row">
    <el-button>Default</el-button>
    <el-button type="primary">Primary</el-button>
  </div>
</template>
```

原文件还有 success、info、warning、danger 配色，以及 plain、round、dashed、circle 等分组。其中 `dashed` 是较新版本才有的属性，你的 2.8.4 用不了，别照抄。

**逐句讲解**

| 写法 | 意思 |
| --- | --- |
| `<el-button>` | 标签名就是组件名。因为全局注册过，页面里不用 import |
| 标签中间的文字 `Default` | 按钮上显示的内容，Vue 里叫默认插槽 |
| `type="primary"` | 属性，控制配色。不写就是默认白底 |
| 属性前面有没有冒号 | 没冒号表示传字符串字面量；有冒号如 `:loading="x"` 表示绑定一个 JS 变量。步骤 6 会用到后者 |

**你动手**

把按钮放进 template，文字改成「登录」，`type` 用 `primary`。script 这一步仍然不用写。

**验收**

页面出现蓝色按钮。再把标签故意改成 `<el-buttonn>`，控制台会出现 `Failed to resolve component` 警告，改回来警告消失。这个反证能确认你确实在用组件库，而不是浏览器把未知标签当普通 HTML 渲染了。

### 可选一步：给页面加个白底卡片（想练「找 UI」就做）

**这一步干什么**

用 `el-card` 把标题和按钮装起来，外层套 `src/styles/index.css` 里现成的 `.auth-container`、卡片上用 `.auth-card`。

**为什么这么干**

这一步只影响外观，不碰逻辑，单独做一次正好练「按分类去找展示型组件」这个动作。以后做文章列表找 Card、Table、Tag，走的是同一套路。

**去哪找**

Overview → Data → Card。官方示例 `docs/examples/card/basic.vue`。

**官方源码**

文件全文，只有几行：

```vue
<template>
  <el-card style="max-width: 480px">
    <template #header>
      <div class="card-header">
        <span>Card name</span>
      </div>
    </template>
    <p v-for="o in 4" :key="o" class="text item">{{ 'List item ' + o }}</p>
    <template #footer>Footer content</template>
  </el-card>
</template>
```

**逐句讲解**

| 写法 | 意思 |
| --- | --- |
| `<el-card>` | 一个带边框和阴影的容器，内容写在标签中间 |
| `<template #header>` | 具名插槽，往卡片头部放内容。不写就没有头部，卡片只剩正文 |
| `v-for="o in 4"` | 官方示例用来造 4 行占位文字，和你的登录页无关 |
| `style="max-width: 480px"` | 官方示例限宽用。本项目 `.auth-card` 已经设了 380px，不用照抄 |

**你动手**

外层 div 加 `class="auth-container"`，`el-card` 加 `class="auth-card"`，把标题和按钮挪进去。这一步不改 script，也不发请求。

**验收**

页面居中出现白色卡片，标题和按钮都在卡片里，控制台没有新报错。

### 步骤 3：让按钮真的发出一次登录请求

**这一步干什么**

给按钮绑点击事件，调用现成的 `login()`，把返回结果打印到控制台。用户名密码先写死一组已注册的账号。

**为什么这么干**

先把「浏览器 → Vite 代理 → Go 后端 → 返回」这条链路验通，再考虑界面长什么样。输入框留到步骤 4。顺序反过来，一旦拿不到数据，就分不清是请求写错了还是 `v-model` 没接住值。

**去哪找**

不需要组件，用 Vue 的事件绑定 `@click`。

**几个必须知道的点**

| 点 | 说明 |
| --- | --- |
| `@click="onSubmit"` | `v-on:click` 的简写，等号里写函数名 |
| `login(data)` | 来自 `api/user.ts`，参数是 `{username, password}`，返回 `Promise<LoginResp>` |
| 拦截器已经拆包 | `utils/request.ts` 在 `code === 0` 时 `return res.data`，所以 `await login(...)` 拿到的是 `{token, user}`，页面里别再写 `res.data.data` |
| URL 只写 `/login` | axios 的 `baseURL` 是 `/api`，Vite 再代理到 8080 |
| token 自动带 | 请求拦截器会加 `Authorization: Bearer`。登录时还没有 token，不加，正常 |
| 用 `async` 函数 | 请求是异步的，要 `await`；用 `try / catch` 接住失败 |

**你动手**

在 script 里 import `login`，写一个 async 函数，函数里 `try / catch`，成功时 `console.log` 结果，按钮上加 `@click`。账号密码先当常量写。

**验收**

按 F12 打开 Network，点按钮，看到一条 `POST /api/login`，Status 200，Response 是 `{"code":0,...,"data":{"token":"..."}}`，Console 里打印出 `{token, user}` 对象。换成错密码，能看到 401 和错误提示。

### 步骤 4：两个输入框，把用户打的字接住

**这一步干什么**

加两个 `el-input`，把输入内容接到变量里，再把步骤 3 写死的常量换成这两个变量。

**为什么这么干**

表单页的本质是收集输入。Vue 用 `v-model` 把输入框和变量连起来，后面每一个页面都要用这个机制。先单独练它，别和表单校验混在一起。

**去哪找**

Overview → Form → Input。官方示例 `docs/examples/input/basic.vue` 和 `docs/examples/input/password.vue`。

**官方源码**

普通输入框，`docs/examples/input/basic.vue` 全文：

```vue
<template>
  <el-input v-model="input" style="width: 240px" placeholder="Please input" />
</template>

<script lang="ts" setup>
import { ref } from 'vue'

const input = ref('')
</script>
```

密码框，`docs/examples/input/password.vue` 节选的第一个输入框：

```vue
<el-input
  v-model="input"
  type="password"
  placeholder="Please input password"
  show-password
/>
```

原文件还有第二个带自定义 `#password-icon` 插槽的写法，这一阶段用不上。

**逐句讲解**

| 写法 | 意思 |
| --- | --- |
| `ref('')` | 造一个响应式变量。变量的值变了，用到它的界面跟着变 |
| `v-model="input"` | 双向绑定。输入框显示 `input` 的值；用户打字，`input` 也被改回去。它把「显示」和「监听输入」合成一句 |
| `placeholder` | 空白时的灰色提示字 |
| `type="password"` | 输入内容显示成圆点 |
| `show-password` | 后面加一个眼睛图标，点一下切换明文。属性不带值，等价于 `:show-password="true"` |
| `style="width: 240px"` | 官方示例为了好看加的宽度。本项目外层样式会限宽，可以不写 |

**你动手**

建两个变量（`username`、`password`），各绑一个 `el-input`，密码那个加 `type="password"` 和 `show-password`。placeholder 按 1.4 的后端规则写提示文字。把步骤 3 里的常量换成变量。

**验收**

在两个框里打字，点按钮，Network 里请求体的 `username` / `password` 变成你打的内容；Console 里也能看到变量值跟着变。

### 步骤 5：把散件装进表单，加校验

**这一步干什么**

用 `el-form` 包住两个输入框和按钮，加「必填 + 长度」校验，点按钮时先校验，通过了才发请求。

**为什么这么干**

散着的输入框没有「整体」概念。`el-form` 一次给你三件事：label 对齐的布局、集中定义的规则、一个能调 `validate()` 的组件实例。前端先挡掉明显不合法的输入，能少发一次注定失败的请求，也少消耗一次限流令牌。

**去哪找**

Overview → Form → Form。官方示例 `docs/examples/form/validation.vue`。

**官方源码**

下面是官方文件的节选。原示例的 `ruleForm` 有 11 个字段、`rules` 有一长串，这里只留 `name` 一条规则，`submitForm` 保持原样：

```vue
<template>
  <el-form
    ref="ruleFormRef"
    :model="ruleForm"
    :rules="rules"
    label-width="auto"
  >
    <el-form-item label="Activity name" prop="name">
      <el-input v-model="ruleForm.name" />
    </el-form-item>
    <el-form-item>
      <el-button type="primary" @click="submitForm(ruleFormRef)">
        Create
      </el-button>
    </el-form-item>
  </el-form>
</template>

<script lang="ts" setup>
import { reactive, ref } from 'vue'
import type { FormInstance, FormRules } from 'element-plus'

const ruleFormRef = ref<FormInstance>()
const ruleForm = reactive({ name: '' })
const rules = reactive<FormRules>({
  name: [
    { required: true, message: 'Please input Activity name', trigger: 'blur' },
    { min: 3, max: 5, message: 'Length should be 3 to 5', trigger: 'blur' },
  ],
})

const submitForm = async (formEl: FormInstance | undefined) => {
  if (!formEl) return
  await formEl.validate((valid, fields) => {
    if (valid) {
      console.log('submit!')
    } else {
      console.log('error submit!', fields)
    }
  })
}
</script>
```

**逐句讲解**

| 写法 | 意思 |
| --- | --- |
| `reactive({...})` | 造一个响应式对象，适合表单这种「一组字段」。`ref` 适合单个值 |
| `:model="ruleForm"` | 冒号表示绑定 JS 对象，把整份数据交给 form。少了它，form 不知道要校验谁 |
| `:rules="rules"` | 规则表，键名必须和 `model` 里的字段名一致 |
| `prop="name"` | 告诉 `el-form-item` 去 rules 里找哪条规则。名字对不上，校验会静默失效，不报错也不拦 |
| `required` / `min` / `max` | 必填 / 最短 / 最长 |
| `trigger: 'blur'` | 什么时候校验，这里是输入框失去焦点时。改成 `change` 就是值一变就校验 |
| `label-width="auto"` | 官网示例的写法，让 label 宽度自适应。如果你在本机版本上看到 label 挤在一起，换成具体像素值如 `80px` |
| `ref="ruleFormRef"` | 给组件实例起个引用，`ruleFormRef.value.validate()` 才能调到它自己的方法 |
| `FormInstance` / `FormRules` | TypeScript 类型，用 `import type` 从 element-plus 引进来，属性写错时编辑器会提示 |
| `validate()` | 返回 Promise。全部通过会 resolve，不通过会 reject。用 `try / catch` 或 `.catch(() => false)` 接住，别让控制台冒未捕获异常 |

**规则要和后端对齐**

从 `internal/user/service.go` 核对：用户名长度 3 到 32，密码 8 到 72 字节。前端 `rules` 照这个写，别自创范围。前端规则和后端不一致时，用户会遇到「页面说合法、后端返回 400」的怪事。

**你动手**

加 `el-form` 包住现有两个输入框；把两个零散变量改成 `reactive` 对象里的字段；写 `rules`；在发请求前先 `validate()`，不通过就 `return`。

**验收**

空着点按钮，两个框下面出现红字，Network 里没有新请求；用户名填 2 个字符被拦下；填合法值能正常发出请求。

### 步骤 6：给反馈，别让人连点

**这一步干什么**

请求期间按钮转圈并禁止再点，成功给绿色提示，失败给红色提示。

**为什么这么干**

HTTP 请求有延迟。不给反馈，用户会以为没点上而反复点。本项目按 IP 限流，容量 10、每秒补 2 个，连点很容易撞 429。另外后端失败时 `message` 里已经有具体原因，要让用户看见。

**去哪找**

Basic → Button 文档的 Loading 节；Feedback → Message，官方示例 `docs/examples/message/basic.vue`。

**官方源码**

`docs/examples/message/basic.vue` 的脚本部分：

```vue
<script lang="ts" setup>
import { ElMessage } from 'element-plus'

const open = () => {
  ElMessage('This is a message.')
}
</script>
```

同一组方法还有 `ElMessage.success('...')` 和 `ElMessage.error('...')`，官网 Message 页有列。

Button 的 `docs/examples/button/loading.vue` 里写的是不带值的 `loading` 属性，那是静态演示。实际项目要绑变量：

```vue
<el-button type="primary" :loading="loading">登录</el-button>
```

**逐句讲解**

| 写法 | 意思 |
| --- | --- |
| `:loading="loading"` | 冒号把属性绑到 JS 变量。变量为 `true` 时按钮显示转圈图标并禁止点击 |
| `ElMessage` | 一个函数，不用写进 template，直接调用就弹出顶部提示 |
| `.success` / `.error` | 同一函数的语义变体，配色和图标不同 |
| `try / finally` | 不管成功失败都要把 `loading` 改回 `false`，否则按钮会一直转 |

**一个容易重复弹窗的点**

`utils/request.ts` 的响应拦截器已经对 401、429 和通用错误弹过 `ElMessage.error` 了。页面 `catch` 里如果再弹一次，用户会看到两条一样的提示。这一阶段页面里可以只 `console.error`，或者只处理自己关心的错误码。

拦截器还把 `errorCode` 和 `requestId` 挂到了错误对象上。想按错误码分支读 `error.errorCode`；报障时把 `error.requestId` 给后端查日志。

**你动手**

加一个 `loading` 变量，绑到按钮上；发请求前设 `true`，`finally` 里设回 `false`；成功时弹 `ElMessage.success`。

**验收**

点一下按钮立刻转圈，请求返回后恢复；成功看到绿提示；连点不会叠出多个在途请求；密码错时只出现一条错误提示。

### 步骤 7：登录成功之后去哪

**这一步干什么**

把 token 存下来，跳到文章列表。

**为什么这么干**

路由守卫每次跳转都读 `getToken()`。token 不落盘，跳过去会被立刻弹回 `/login`，看起来像「登录没生效」。这一步也是理解前后端怎么交接登录态的关键。

**去哪找**

不需要组件。用 `useUserStore()` 或 `setToken()`，以及 `useRouter()`。

**几个必须知道的点**

| 点 | 说明 |
| --- | --- |
| store 已经封装好 | `store/modules/user.ts` 的 `login(data)` 内部调了 `setToken`，还把用户名存进 store。页面调它一次就够 |
| 存哪 | `utils/auth.ts` 写在 `localStorage` 的 `forum_token`，刷新页面还在 |
| 守卫怎么走 | `router/index.ts` 的 `beforeEach`：有 token 还去 `/login` 会被送去 `/articles`；没 token 去 `/articles` 会被送去 `/login` |
| `replace` 和 `push` | `replace` 不留历史记录，登录页不该能按浏览器后退键退回去 |

**你动手**

登录成功后调 store 的 `login`、弹成功提示、`router.replace('/articles')`。

**验收**

登录成功跳到文章列表；刷新页面仍停在列表；点浏览器后退不会回到登录表单；手动删掉 `localStorage` 里的 `forum_token` 再刷新，会被送回 `/login`。

## 5. 这一阶段最容易踩的坑

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 连点几下出现 429 | 后端按 IP 限流，容量 10、每秒补 2 个 | 等几秒再试。`utils/request.ts` 已注释说明不要自动重试，重试本身也吃令牌 |
| 页面里取不到数据 | 拦截器已把 `data` 拆出来，又写了一次 `.data` | `await login()` 直接用返回值 |
| 一登录就被弹回 `/login` | token 没存进 `localStorage` | 检查步骤 7 有没有调 store 的 `login` 或 `setToken` |
| 输入框打字，变量没变 | 忘了 `v-model`，或者字段名和 `:model` 里的对不上 | 对照步骤 4 检查绑定 |
| 校验完全不生效，也不报错 | `el-form-item` 的 `prop` 和 `rules` 的键名不一致 | 两边名字必须逐字相同 |
| 报错 `Failed to resolve component` | 标签名拼错，或该组件当前版本还没有 | 对照 2.3 的版本提醒，先换回基础属性 |
| 控制台冒未捕获 Promise 异常 | `validate()` 或请求失败没接住 | `try / catch` 或 `.catch(() => false)` |
| 输了正确账号却 400 | 用户名不足 3 位或密码不足 8 位，后端 `validateCredentials` 会拒 | 按 1.4 的规则填 |
