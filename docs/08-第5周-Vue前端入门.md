# 08 第 5 周 Vue 前端入门（对接 forum-backend）

## 0. 范围与读法

### 0.1 这份文档做什么

给后端每个已实现接口配一个能点得动的页面。页面样式极简，只求把后端的机制跑通、看得见。

覆盖：注册、登录、文章列表与分页、文章详情、发文章、删文章、评论列表、发评论、删评论、点赞与取消、热榜、站内通知列表、全部已读、WebSocket 实时推送、在线人数。

不做：组件库、TypeScript、Pinia、单元测试、SSR、权限系统、打包部署。这些加进来会让学习重点从「后端链路」偏到「前端工程化」。

### 0.2 一次只做一节

按第 2 节到第 5 节的顺序落文件。每写完一节，`npm run dev` 打开页面点一次，确认能跑再进下一节。第 2.4 有逐文件落盘顺序表，标了每一步能验证什么。

## 1. 后端接口真实清单

来源：`internal/router/router.go`、`internal/handler/*.go`、`internal/handler/dto.go`、`api/swagger/swagger.json`。swagger 少了 `DELETE /api/articles/:id`，以路由表为准。

| 方法 | 路径 | 需要 token | 请求体或参数 | `data` 形状 |
| --- | --- | --- | --- | --- |
| POST | `/api/register` | 否 | `{username, password}` | `userResp` |
| POST | `/api/login` | 否 | `{username, password}` | `{token, user}` |
| GET | `/api/articles` | 否 | `page`, `page_size` | `{list, total, page, page_size}` |
| GET | `/api/articles/hot` | 否 | `limit`，1 到 100 | `{list}` |
| GET | `/api/articles/:id` | 否 | 路径 id | `articleResp` 加 `like_count` |
| GET | `/api/articles/:id/comments` | 否 | `page`, `page_size` | `{list, total, page, page_size}` |
| POST | `/api/articles` | 是 | `{title, content}` | `articleResp` |
| DELETE | `/api/articles/:id` | 是 | 路径 id | `null` |
| POST | `/api/articles/:id/comments` | 是 | `{content}` | `commentResp` |
| DELETE | `/api/comments/:id` | 是 | 路径 id | `null` |
| PUT | `/api/articles/:id/like` | 是 | 路径 id | `{article_id, like_count, changed, liked}` |
| DELETE | `/api/articles/:id/like` | 是 | 路径 id | 同上 |
| GET | `/api/notifications` | 是 | `page`, `page_size` | `{list, total, unread_count, page, page_size}` |
| PUT | `/api/notifications/read-all` | 是 | 无 | `{affected}` |
| GET | `/api/ws/stats` | 否 | 无 | `{online_users, online_conns}` |
| GET | `/api/ws/notifications?token=` | 查询参数传 token | 无 | WebSocket 升级 |

### 1.1 统一响应包

全部接口走 `pkg/response`：

```json
{"code": 0, "message": "ok", "data": {}}
```

失败是 HTTP 非 2xx 加 `code: 1`、`data: null`，错误文案在 `message`。所以 axios 拦截器可以直接把 `res.data.data` 解出来，页面里不用层层取 `data.data.data`。

### 1.2 token 怎么带

`internal/middleware/jwt.go` 要求 `Authorization: Bearer <token>`，少 Bearer 前缀会 401。`config/config.yaml` 的 `jwt.expire` 是 24 小时，过期后返回「登录已过期，请重新登录」。

WebSocket 是例外。浏览器 `new WebSocket()` 不能自定义请求头，`internal/handler/ws.go` 从查询参数读 `token`。

### 1.3 限流是这个前端最容易踩的坑

`internal/router/router.go` 把限流挂在 `/api` 整组上，参数 `Capacity=10, Rate=2`，按 `c.ClientIP()` 分桶。所有接口共用一个桶，包含登录、列表、静态数据。

一次进首页会发四个请求：通知未读数、在线人数、文章列表、热榜。连刷三次首页就会 429。429 带 `Retry-After` 秒数，来源 `internal/middleware/ratelimit.go`。

前端的应对写在 3.1：429 不自动重试，把等待秒数显示出来。自动重试本身也要消耗令牌，越重试越晚恢复。

### 1.4 六个必须知道的契约边角

| 边角 | 实际行为 | 前端怎么处理 |
| --- | --- | --- |
| 列表没有点赞数 | `articleResp` 无 `like_count`，只有详情的 `articleDetailResp` 有 | 列表只显示标题、作者、时间。点赞数从详情或热榜取 |
| 详情的 swagger 定义滞后 | 注解写的是 `data=articleResp`，源码 `Detail` 已改调 `toArticleDetailResp`，实际多 `like_count` | 以源码为准，别按 swagger 的类型生成前端模型 |
| 新建响应没有作者 | `Create` 没 `Preload("User")`，`author` 字段缺席 | 发文成功后跳详情页重新拉一次，不要在成功回调里读作者 |
| 没有「我是否已点赞」接口 | 只有点赞与取消的返回值带 `liked` | 详情页放两个独立按钮，见 5.4。不要猜状态 |
| 注册不自动登录 | `/api/register` 只返回用户信息 | 前端注册成功后自己再调一次 `/api/login` |
| 通知里没有用户名 | 瘦事件只带 `actor_id`，用户查询接口项目里没有 | 文案写「用户 5」，等后端补用户查询再美化 |

### 1.5 校验规则

`internal/service/user.go` 的 `validateCredentials`：用户名 3 到 32 位且只含字母数字下划线，密码 8 到 72 字节。文章标题非空且不超 128 字节、正文非空且不超 50000 字节。评论正文非空且不超 10000 字节。分页 `page >= 1`，`page_size` 1 到 50。前端做同样的长度校验能少一次 400 请求。

### 2.3 vite.config.js

后端没有 CORS 中间件（`internal/router/router.go` 里搜不到 `Access-Control`）。浏览器从 `localhost:5173` 直接请求 `127.0.0.1:8080` 会被同源策略挡住。开发期必须用 Vite 代理，让浏览器只跟 5173 打交道。

```js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  server: {
    port: 5173,
    proxy: {
      '/api': {
        target: 'http://127.0.0.1:8080',
        changeOrigin: true,
        ws: true
      }
    }
  }
})
```

`ws: true` 让 `/api/ws/notifications` 的升级请求也走代理。`changeOrigin` 改的是 Host 头，不会改 Origin 头。

**还有一个坑必须处理。** `internal/handler/ws.go` 的 `allowedOrigins` 白名单只有 `app.forum.com` 与 `127.0.0.1:8080`。浏览器在 `http://localhost:5173` 打开页面，握手带的 Origin 是 `http://localhost:5173`，白名单里没有，握手会被拒 403。代理转发不会帮你改 Origin。

两条走法：

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| A 改后端白名单 | 在 `internal/handler/ws.go` 的 `allowedOrigins` 加一行 `"localhost:5173": true`，重启后端 | 推荐。前端保持干净，改动一行，语义正确 |
| B 代理里覆写 Origin | 在 `vite.config.js` 的代理项里加 `configure` 钩子，把 `proxyReq` 与 `proxyReqWs` 的 `Origin` 头改成 `http://127.0.0.1:8080` | 不动后端，代价是伪造来源头。只适合开发期，正式部署不能这么干 |

方案 A 要按你实际访问地址写。用 `127.0.0.1:5173` 打开页面就加 `"127.0.0.1:5173": true`。本文档后续代码假定方案 A 已做完。这一步需要你手动改 Go 源码，本文档没有改动后端。

## 3. 公共层

### 3.1 src/api/client.js

统一解包、统一带 token、统一处理 401 与 429。

```js
import axios from 'axios'
import { getToken, clearToken } from '../auth'

const http = axios.create({
  baseURL: '/api',
  timeout: 8000
})

http.interceptors.request.use(function (config) {
  const token = getToken()
  if (token !== null && token !== '') {
    config.headers.Authorization = 'Bearer ' + token
  }
  return config
})

http.interceptors.response.use(
  function (res) {
    return res.data.data
  },
  function (error) {
    const res = error.response
    if (res === undefined) {
      throw new Error('网络不通，确认后端、MySQL、Redis 都已启动')
    }

    let message = '请求失败'
    if (res.data !== null && typeof res.data === 'object') {
      if (typeof res.data.message === 'string') {
        message = res.data.message
      }
    }

    if (res.status === 429) {
      const wait = Number(res.headers['retry-after'])
      const err = new Error('请求太频繁，请 ' + wait + ' 秒后再试')
      err.waitSec = wait
      throw err
    }

    // 登录接口自己返回 401 表示密码错，别跳登录页，否则错误提示会被刷新冲掉。
    const isLoginCall = error.config !== undefined && error.config.url === '/login'
    if (res.status === 401 && isLoginCall === false) {
      clearToken()
      window.location.assign('/login')
    }
    throw new Error(message)
  }
)

export default http
```

429 为什么不自动重试。重试请求本身也过限流脚本，也要扣令牌。桶空时立刻重试只会把 `last_ms` 往后推，恢复时间反而变长。读 `Retry-After` 并把等待时间交给用户，是这个后端参数下更合理的行为。

### 3.3 src/auth.js

只用 localStorage，不引状态管理库。

```js
const TOKEN_KEY = 'forum_token'
const USER_KEY = 'forum_user'

export function getToken() {
  return localStorage.getItem(TOKEN_KEY)
}

export function setToken(token) {
  localStorage.setItem(TOKEN_KEY, token)
}

export function clearToken() {
  localStorage.removeItem(TOKEN_KEY)
  localStorage.removeItem(USER_KEY)
}

export function isLoggedIn() {
  const token = getToken()
  return token !== null && token !== ''
}

export function getUser() {
  const raw = localStorage.getItem(USER_KEY)
  if (raw === null) {
    return null
  }
  let user = null
  try {
    user = JSON.parse(raw)
  } catch (e) {
    user = null
  }
  return user
}

export function setUser(user) {
  localStorage.setItem(USER_KEY, JSON.stringify(user))
}
```

### 3.4 src/router.js

需要登录的页面用 `meta.needLogin` 标记。守卫只挡跳转，后台数据权限由 JWT 中间件负责。

```js
import { createRouter, createWebHistory } from 'vue-router'
import { isLoggedIn } from './auth'
import HomeView from './views/HomeView.vue'
import LoginView from './views/LoginView.vue'
import NewArticleView from './views/NewArticleView.vue'
import ArticleView from './views/ArticleView.vue'
import NotificationsView from './views/NotificationsView.vue'

const routes = [
  { path: '/', component: HomeView },
  { path: '/login', component: LoginView },
  { path: '/articles/new', component: NewArticleView, meta: { needLogin: true } },
  { path: '/articles/:id', component: ArticleView },
  { path: '/notifications', component: NotificationsView, meta: { needLogin: true } }
]

const router = createRouter({
  history: createWebHistory(),
  routes
})

router.beforeEach(function (to) {
  if (to.meta.needLogin === true && isLoggedIn() === false) {
    return '/login?next=' + encodeURIComponent(to.fullPath)
  }
  return true
})

export default router
```

`/articles/new` 写在 `/articles/:id` 前面，阅读上更清楚。vue-router 4 按匹配打分，静态段优先于动态段，两个顺序都能工作。

### 3.6 src/App.vue

顶部导航、未读红点、在线人数、退出登录。第 9 步再把 WS 接进来。

```vue
<script setup>
import { ref, onMounted, onUnmounted } from 'vue'
import { useRouter } from 'vue-router'
import { isLoggedIn, getUser, clearToken } from './auth'
import { listNotifications, getOnlineStats } from './api'
import { connect, disconnect } from './ws'

const unread = ref(0)
const online = ref(null)
const flash = ref('')
const router = useRouter()
let timer = null

function refreshBadge() {
  if (isLoggedIn() === false) {
    unread.value = 0
    return
  }
  listNotifications(1, 1).then(function (data) {
    unread.value = data.unread_count
  }).catch(function () {})
}

function refreshOnline() {
  getOnlineStats().then(function (data) {
    online.value = data
  }).catch(function () {})
}

function onPush(data) {
  unread.value = unread.value + 1
  flash.value = '用户 ' + data.actor_id + ' 有新动作'
}

function onReconnect() {
  // WebSocket 只保证「尽力推一次」。断线期间落库的通知要靠这次补拉。
  refreshBadge()
}

function logout() {
  clearToken()
  disconnect()
  router.push('/login')
}

onMounted(function () {
  refreshBadge()
  refreshOnline()
  timer = setInterval(refreshOnline, 30000)
  connect(onPush, onReconnect)
})

onUnmounted(function () {
  if (timer !== null) {
    clearInterval(timer)
  }
})
</script>

<template>
  <div class="wrap">
    <nav>
      <router-link to="/">首页</router-link>
      <router-link to="/articles/new">发文章</router-link>
      <router-link to="/notifications">通知 ({{ unread }})</router-link>
      <span class="muted" v-if="online !== null">
        在线 {{ online.online_users }} 人 / {{ online.online_conns }} 连接
      </span>
      <span style="margin-left:auto">
        <span class="muted" v-if="getUser() !== null">{{ getUser().username }}</span>
        <button v-if="isLoggedIn()" @click="logout">退出</button>
        <router-link v-else to="/login">登录</router-link>
      </span>
    </nav>
    <p class="err" v-if="flash !== ''">{{ flash }}</p>
    <router-view />
  </div>
</template>
```

`connect` 在第 5.6 定义。第 9 步之前先把 `ws.js` 建一个空壳，导出两个什么都不做的函数，页面就能先跑起来。这也符合一次只做一节的节奏。

顶部导航首屏会发两次请求，加上首页两次，一次进站共四次。刷新频繁时按 1.3 的提示等 `Retry-After` 秒数。

### 4.1 src/views/LoginView.vue

登录与注册共用一个表单。注册成功后自动再调一次登录，因为后端注册不发 token。

```vue
<script setup>
import { ref } from 'vue'
import { useRoute } from 'vue-router'
import { register, login } from '../api'
import { setToken, setUser } from '../auth'

const username = ref('')
const password = ref('')
const error = ref('')
const route = useRoute()

function checkInput() {
  const name = username.value
  if (name.length < 3 || name.length > 32) {
    return '用户名需要 3 到 32 位'
  }
  for (let i = 0; i < name.length; i = i + 1) {
    const ch = name[i]
    const ok = (ch >= 'a' && ch <= 'z') || (ch >= 'A' && ch <= 'Z') ||
      (ch >= '0' && ch <= '9') || ch === '_'
    if (ok === false) {
      return '用户名只能用字母、数字、下划线'
    }
  }
  if (password.value.length < 8) {
    return '密码至少 8 位'
  }
  return ''
}

function afterLogin(data) {
  setToken(data.token)
  setUser(data.user)
  let next = route.query.next
  if (typeof next !== 'string') {
    next = '/'
  }
  // 整页重载让 App.vue 重新挂载，onMounted 里的 WebSocket 才会连上。
  // 代价是多一次首屏请求，在共用限流桶的后端上要留意 429。
  window.location.assign(next)
}

function doLogin() {
  error.value = checkInput()
  if (error.value !== '') {
    return
  }
  login(username.value, password.value).then(afterLogin).catch(function (e) {
    error.value = e.message
  })
}

function doRegister() {
  error.value = checkInput()
  if (error.value !== '') {
    return
  }
  register(username.value, password.value).then(function () {
    return login(username.value, password.value)
  }).then(afterLogin).catch(function (e) {
    error.value = e.message
  })
}
</script>

<template>
  <h2>登录 / 注册</h2>
  <div class="card">
    <label>用户名</label>
    <input v-model="username" placeholder="3-32 位字母数字下划线" />
    <label>密码</label>
    <input v-model="password" type="password" placeholder="至少 8 位" />
    <p class="err" v-if="error !== ''">{{ error }}</p>
    <button @click="doLogin">登录</button>
    <button @click="doRegister">注册并登录</button>
  </div>
</template>
```

`checkInput` 用最直白的逐字符循环，规则与 `internal/service/user.go` 一致。前端先挡一层，能省掉一次必然 400 的请求，也省一个令牌。

### 4.4 src/views/ArticleView.vue

详情、点赞、评论、删除都放这一页。

点赞这里放两个独立按钮。后端没有「当前用户是否已点赞」的查询接口，刷新页面后前端无从得知状态。若靠本地变量猜，用户刷新后再点一次「取消」会变成真的取消点赞，属于前端制造的数据错误。两个按钮把判断交回给后端：`changed` 为 false 时提示「本次没有变化」。

### 4.6 src/ws.js

浏览器 WebSocket 会自动回服务端的 Ping，前端不需要写心跳。`internal/realtime/client.go` 的 `ReadLoop` 也不处理任何客户端业务消息，别往里发东西。

```js
import { getToken } from './auth'
import { wsURL } from './api'

let socket = null
let retryTimer = null
let closedByUser = false
let onMessage = null
let onReconnect = null
let openedBefore = false

function open(token) {
  socket = new WebSocket(wsURL(token))

  socket.onopen = function () {
    if (openedBefore === true && onReconnect !== null) {
      onReconnect()
    }
    openedBefore = true
  }

  socket.onmessage = function (event) {
    let msg = null
    try {
      msg = JSON.parse(event.data)
    } catch (e) {
      return
    }
    if (msg.type === 'notification.created' && onMessage !== null) {
      onMessage(msg.data)
    }
  }

  socket.onclose = function () {
    if (closedByUser === true) {
      return
    }
    retryTimer = setTimeout(function () {
      open(token)
    }, 3000)
  }
}

export function connect(handleMessage, handleReconnect) {
  const token = getToken()
  if (token === null || token === '') {
    return
  }
  onMessage = handleMessage
  onReconnect = handleReconnect
  closedByUser = false
  open(token)
}

export function disconnect() {
  closedByUser = true
  if (retryTimer !== null) {
    clearTimeout(retryTimer)
    retryTimer = null
  }
  if (socket !== null) {
    socket.close()
    socket = null
  }
  openedBefore = false
}
```

重连后调 `onReconnect` 补拉列表，理由写在 `docs/04c` 第 0 节：可靠性的真相源是 MySQL 里的 `notifications` 行，WebSocket 只把「已经有了」提前告诉浏览器。断线期间的通知一条都不会通过 WS 补发。

`App.vue` 在 `onMounted` 里调 `connect`，退出登录时调 `disconnect`。如果登录发生在已挂载的 `App.vue` 里，只做 `router.push` 不会重新触发 `onMounted`，WS 就一直没连上。4.1 的 `afterLogin` 用 `window.location.assign(next)` 整页重载，就是为了让 `connect` 一定跑一次。代价是首屏多发几个请求，共用限流桶时要留意 429。

## 5. 按后端功能逐条验收

| # | 操作 | 预期 | 对应后端机制 |
| --- | --- | --- | --- |
| 1 | 注册 `alice` / 密码 8 位 | 自动登录，顶部显示用户名 | `bcrypt` 哈希，注册不发 token |
| 2 | 用 `alice` 发一篇文章 | 跳详情，标题正文正确 | 事务写入，详情缓存失效 |
| 3 | 回首页刷新 | 列表出现新文章，带作者 | `Preload("User")` |
| 4 | 翻页 | `page` 变化，`total` 不变 | `parsePage`，最大 50 |
| 5 | 用另一个账号 `bob` 点赞该文章 | 详情点赞数加一，热榜出现该文 | `syncHotScore` 写绝对值 |
| 6 | `bob` 再点一次赞 | 提示「已经点过赞了」 | 唯一索引，`changed: false` |
| 7 | `bob` 评论 | 评论列表出现，带作者 | 事务加 outbox 事件 |
| 8 | 用 `alice` 打开通知页 | 两条通知，未读数为 2 | Outbox + Stream + 消费组 |
| 9 | 两个浏览器标签都登录 `alice`，`bob` 再点赞 | 红点实时加一 | WebSocket Hub 按 userID 广播 |
| 10 | 点「全部标为已读」 | 未读归零，列表 `is_read` 全 true | 单条 UPDATE |
| 11 | 点评论通知 | 跳到文章并滚到那条评论 | `target_type` 分支 |
| 12 | `alice` 删除文章 | 回首页，列表消失 | 事务里先清评论与点赞 |
| 13 | 快速刷新首页五六次 | 出现 429 与等待秒数 | 令牌桶，按 IP 共用 |
| 14 | 等 24 小时后或手动改坏 token 再发文章 | 跳登录页 | JWT 过期，401 拦截 |

第 8 步需要两个账号。自己给自己的文章点赞或评论，`internal/worker/notify_resolver.go` 里 `article.UserID == p.ActorID` 直接返回，不会生成通知。

## 6. 报错对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 控制台 CORS 报错 | `axios` 直接写了 `http://127.0.0.1:8080` | 全部用 `/api/...` 相对路径，交给代理 |
| 列表 429 且文案带秒数 | 限流桶空了 | 等 `Retry-After` 秒数，减少首屏并发请求 |
| 所有带 token 的请求 401 | 少了 `Bearer` 前缀，或 token 过期 | 检查 `client.js` 拦截器；`jwt.expire` 是 24 小时 |
| 登录密码错也刷新页面 | 401 分支误把登录请求算成过期 | `isLoginCall` 判断已在 3.1 处理 |
| WebSocket 403 | Origin 不在白名单 | 按 2.3 方案 A 加 `localhost:5173` |
| WS 连上又立刻断 | token 通过查询参数传错或过期 | 检查 `wsURL` 与 `encodeURIComponent` |
| 发文后作者显示「信息缺失」 | 新建响应没 Preload | 跳详情重新拉，见 4.3 |
| 删过的文章点进去还显示旧内容 | 详情缓存或空标记未清 | 等 TTL，或查 `InvalidateDetailCache` 是否被调用 |
| 热榜为空但有人点过赞 | 投影尚未初始化或 ready 与 ZSET 状态不一致 | 见 `docs/05b` 的 `projectionLost` 判定 |

## 7. 这套前端的边界

**它能给项目带来什么。** 后端的限流、缓存、Outbox、WebSocket 原本只能靠 curl 与 `wscat` 观察，有了页面之后能在浏览器里连续看到效果。面试演示时，用两个标签页互赞让红点变化，比贴一段日志直观。它也让 1.4 那些契约缺口暴露出来，这些缺口本身就是后端下一步该补的东西。

**它自身没有工程亮点。** 没有组件库与 TypeScript，token 放在 localStorage 有 XSS 风险且没有刷新令牌机制，路由守卫只判断「有没有 token」不判断角色，没有前端测试与错误上报。结论要克制：这份前端的定位是后端链路的可视化验收工具，简历上配一句「用于验证后端接口与实时链路」即可，写成「独立完成前后端分离项目」会被追问前端工程化程度。

**两个由后端设计直接传导到前端的取舍。**

| 取舍 | 前端的代价 | 更彻底的做法 |
| --- | --- | --- |
| 瘦事件只带 id | 通知文案只能显示「用户 5」 | 补批量查用户接口，消费端不变 |
| 全站一个 IP 限流桶 | 首屏四个请求互相挤占，刷新几次就 429 | 读写分组限流，或把静态数据合并成一个聚合接口 |

前者是消息体积小与展示信息量的取舍，后者是保护力度与体验的取舍。两条都谈不上对错，取决于项目规模。单机论坛当前规模下，前端做减法更划算。
